# Changelog

One entry per change set, newest at the bottom.

## 0. The original (January to February 2026)

Built in Replit for the University of Chicago AI integration program, against the
brief in `docs/original-brief.md`. A React page took a CSV of survey answers,
found shared dates with a 4 to 3 to 2 day fallback, filtered 61 destinations by
home city, passport, and the lowest budget, scored the rest, and filled the days
from random activity templates. An evaluation harness was written but never
called. No tests. The last original commit is `3a4bdd5`.

## 1. Planner rewrite and cleanup (Sept 30, 2026, `1784a61`)

Moved planning out of the browser bundle into `planner/`, split by stage, and
fixed what the old version got wrong:

- The crowd penalty checked ids `miami` and `new_york`, which do not exist.
- An explicit 0% budget flex was read as 10%.
- A 4-day trip reported the end of the whole shared window as its end date.
- Puerto Rico was treated as international.
- Home-city matching used substrings ("LA" matched every name containing "la").
- Survey interests like `live_music` never matched destination tags.
- Every $100 saved was worth half an interest match, so the cheapest place won.
- The runner-up could be the winner itself, and `needs_info` stopped at the
  first person missing a field.

Added a fairness component, specific suggested fixes (who blocks the schedule,
whose budget to raise and to what), and must-pass checks in place of the unused
harness. Removed the Replit scaffolding: an empty Express, Postgres, and login
server, 46 unused UI components, about 50 dependencies, and duplicate data.
25 tests.

## 2. Shareable trips (Sept 30, 2026, `85e5c61`)

Replaced CSV upload with a trip flow: create a trip, share a link, friends
answer a mobile form and can edit later, the organizer plans and re-plans, and
the plan shows on the share link. "Try a sample trip" creates a private copy
with six made-up friends dated six weeks out. One fetch-style API serves both
Vercel and the Vite dev server, backed by Neon Postgres behind a store interface
with an in-memory version for tests. Rate limits per IP, trip expiry. 39 tests.

## 3. Claude reads notes and writes the itinerary (Oct 1, 2026, `813145f`)

Claude now turns free-text notes into structured constraints (domestic only,
mobility, diet, tags to avoid, extra interests, nonstop only), which the planner
applies with a new dealbreaker penalty, and writes the itinerary for the chosen
destination. Drafts go through the plan checks plus new ones (nobody left out,
no unknown names) and are retried with feedback up to three times before the
template takes over. Plans carry an agent trace with sources, per-draft check
results, tokens, cost, and time.

Measured the itinerary at low effort (16 s, $0.04) against medium (35 s, $0.06)
with no visible quality difference and chose low. Fixed jsonb encoding in the
Postgres store, found when a cache write failed in the browser. 53 tests.

## 4. Real weather, travel time, and prices (Oct 1, 2026, `f04b11d`)

- Flight time from every home city to every destination, enforced against each
  person's longest-flight answer.
- Weather for the actual dates at the top five destinations: forecast within 16
  days, otherwise a three-year average for those dates, replacing static climate
  tags in scoring.
- Live Google Flights and Google Hotels prices for the winner through SerpApi's
  free plan, checked per person against their own budget, with a move to the
  next destination when someone can no longer afford it. Cached three days and
  capped at 200 searches a month.
- Destinations gained coordinates and airports, generated by
  `scripts/enrich-destinations.ts`.

The plan view gained weather, a per-person cost table with booking links, and the
shortlist. On the sample trip the real cost came out at $776 to $806 per person
against a static estimate of $1,100. 69 tests.

## 5. Deployed (Oct 1, 2026, `f787dd6`, `7ec2610`)

Production at https://grouptrip-planner.vercel.app. The build uses Vercel's
Build Output API: the API is bundled into one function by esbuild, so production
does not depend on Vercel compiling individual TypeScript files. The Node
request adapter is shared with the dev server.

The first deploy was blocked because commits carried the machine's default git
email; the repo now uses the GitHub account's email.

`README.md`, `PRD.md`, `CLAUDE.md`, this file, and `INDEX.md`, with screenshots
